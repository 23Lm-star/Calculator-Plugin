# Development OS v1.2 项目流程规则

## 项目目标

为“王晨扬的计算器”提供可追溯、可独立验证、可审计的 Qt Widgets 桌面交付流程。业务源码、维护测试和流程证据分离保存。

## 目录职责

- `src/`：运行时源码（源代码）。
- `tests/`：维护的产品测试（测试代码）。
- `project-docs/`：流程记录、任务卡、批准事件、报告和证据。
- `project-tools/`：临时测试脚本、生成器和夹具（当前项目暂未声明运行时工具）。
- `docs/ai-workflow/`：v1.0/v1.1 历史记录，只读保留。

## 流程约束

- 当前 `workflow_version`（流程版本）必须为 `v1.2`，所有新任务使用 `project-docs/tasks/<task-id>/`。
- 开发前 Goal（技术目标）必须为 `LOCKED`（已锁定），设计与计划必须有记录；未锁定不得修改业务源码。
- 独立测试、独立审计使用新会话，只能写任务证据目录，不得改源码、配置、既有测试或 Git 历史。
- 每个必需质量门禁必须记录 `PASS`（通过）、`FAIL`（失败）、`NOT_APPLICABLE`（不适用）或 `BLOCKED`（阻塞）及证据；缺少工具按阻塞处理。
- 完整回归必须覆盖 `regression/功能回归清单.yaml` 中所有 `required: true`（必测）功能的成功、失败和跨功能路径。
- 流程、架构、权限、公共接口、依赖、迁移、发布和远程操作必须记录批准事件；不得隐式越过审批边界。
- 任务完成前必须有独立审计和人工审计确认；未完成不得进入集成或发布。

## 数据流与证据

用户需求 -> 任务卡 -> Goal（目标）/Design（设计）/Plan（计划） -> 开发分支 -> 独立测试证据 -> 独立审计 -> 集成候选回归 -> 发布准备。`manifest.yaml`（清单）是事件链的当前投影，事件文件采用追加式 NDJSON（每行一个 JSON 对象）保存历史。
