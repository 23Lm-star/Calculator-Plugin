## Findings

### [P1] ZIP 不是封闭白名单，发布输入目录的新增文件会被递归带入交付物

- 证据：`scripts/release/Package-Release.ps1:64` 至 `:69` 对 `platforms`、`imageformats`、`iconengines`、`translations` 执行递归 `Copy-Item`。实际 ZIP 有 50 项，包含所有 `imageformats/*.dll` 和 `translations/*.qm`，不只是任务卡要求的 `platforms/qwindows.dll`。
- 影响：构建输出目录若混入调试、私密或不受信任文件，脚本会把它们直接放入便携 ZIP 和安装器 Payload。当前 `runtimeNames` 列表不能约束这些目录。
- 修复交接：在 `Package-Release.ps1` 将目录级递归复制替换为明确相对路径白名单。若应用确需额外插件或翻译，逐文件列入清单并校验其存在；打包后列举 ZIP entries，拒绝不在白名单、绝对路径、驱动器前缀、UNC 前缀或包含 `..` 的条目。
- 复测：在受控 Release 输入中加入未列入的 `platforms/unexpected.dll`、`translations/private.txt`，断言二者均不在两个 ZIP；同时断言所有必需运行时仍在包中。

### [P1] 路径泄漏防护覆盖范围不足，且独立测试未验证其报告声称的归档路径安全性

- 证据：`scripts/release/Package-Release.ps1:76` 至 `:85` 只检查 `.ps1`、`.md`、`.cmd`、`.ini`，且仅以区分大小写的 `Contains` 匹配当前 `$projectRoot` 与 `$releasePath`。任何其他 Windows 绝对路径、UNC 路径、插件目录中的文本文件或 ZIP entry 名称均可绕过。
- 证据：`evidence/independent-test/run-independent-validation.ps1:88` 至 `:93` 只扫描解压后 `.ps1`、`.cmd`、`.md` 的盘符路径；它没有检查 ZIP entry 是否有绝对路径或 `..`。但 `evidence/independent-test/commands.md` 表述为“no absolute/traversal archive entry”。
- 影响：发布包可能泄露开发机或其他环境路径；独立测试的“归档路径安全”结论没有对应执行证据。
- 修复交接：路径检测应直接检查归档 entry 名称，并对所有交付文本使用统一的绝对路径规则（Windows 盘符、UNC、扩展路径和 `..` 段），而不是只匹配两个当前目录字符串。检查应在压缩前和压缩后均执行，并将命中 entry/文件作为失败证据输出。
- 复测：添加包含 `C:\\temp\\secret`、`\\\\server\\share`、`..\\escape` 的受控文本/entry 测试样本，分别断言打包失败或条目被拒绝；无泄漏的正式包必须通过完整 entry 与文本扫描。

### [P2] 独立测试报告的 PowerShell 解析覆盖声明不准确

- 证据：独立测试报告和 `commands.md` 都称三个 `scripts/release/*.ps1` 已解析；验证器仅调用 `Test-Parse` 于 `Install-Calculator.ps1` 和 `Package-Release.ps1`（`run-independent-validation.ps1:107` 至 `:110`），未解析 `Create-DesktopShortcut.ps1`。
- 影响：桌面快捷方式脚本是便携包关键路径，当前“全部解析通过”的证据不成立。
- 修复交接：将 `Create-DesktopShortcut.ps1` 纳入独立验证器的 AST 解析断言，并令报告从 JSON/日志实际结果生成或逐项对应，避免叙述与执行脱节。
- 复测：验证日志和 JSON 应出现三个脚本各自的零解析错误断言。

## Passed Checks

- `Install-Calculator.ps1` 在展开 Payload、复制应用、创建桌面快捷方式及确认 EXE 后，才从 `$InstallDirectory\\vc_redist.x64.exe` 调用 VC 运行库。
- 调用参数为 `/install /quiet /norestart`，使用 `-Wait -PassThru`；仅退出码 `0` 和 `3010` 成功，`3010` 输出重启提示，其余退出码抛出包含退出码和部署目录手动执行路径的错误。
- 独立测试证据对 `0`、`3010`、`1603` 使用进程级双替身覆盖了这些分支；没有在开发机执行真实 VC 安装程序，符合任务约束。
