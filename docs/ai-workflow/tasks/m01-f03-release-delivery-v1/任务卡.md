# M01-F03 | 发布交付物生成与部署脚本化

- Internal ID: `m01-f03-release-delivery-v1`
- Workflow version: `v1.1`
- Task card version: `v1.2`
- Status: 开发中
- Business objective: 其他人完整拉取或下载当前项目后，无需 Qt、Visual Studio、手动打包或额外 Installer ZIP，直接运行仓库内 `scripts/release/Install-Calculator.cmd` 即可自动安装“王晨扬的计算器”。
- In scope: `release/Payload.zip` 受跟踪载荷、发布打包/安装/快捷方式脚本、运行依赖检查、使用说明和验证证据。
- Explicitly out of scope: 编译过程修改、应用业务代码、在线升级、远程发布、推送、部署。
- Dependencies and integration baseline: `integration@1ce0e9a`; 维护者重建载荷时的 Release 输入目录为 `build/v1.1-app/release/`，应包含 Qt 运行时、`platforms/qwindows.dll`、MSVC x64 CRT 与 `vc_redist.x64.exe`。
- Allowed paths: `scripts/release/`, `release/`, 已明确提交的安装器载荷文件、`.gitignore`（仅在精确载荷文件需要跟踪时）、`docs/ai-workflow/`。
- Acceptance criteria:
  1. 完整克隆或下载项目后，`scripts/release/Install-Calculator.cmd` 能定位随仓库提交的 `release/Payload.zip`；用户无需运行 `Package-Release.ps1`。
  2. Payload 含 EXE、Qt 运行时、`platforms/qwindows.dll`、MSVC CRT、`vc_redist.x64.exe`、快捷方式脚本和 README，且 ZIP 条目仅来自白名单、无绝对路径、UNC 或 `..`。
  3. `Package-Release.ps1` 保留并能从相对 Release 输入稳定重建受跟踪的 `release/Payload.zip`，不写入开发机绝对路径。
  4. README 的唯一推荐步骤为完整获取项目后进入 `scripts/release` 运行 `Install-Calculator.cmd`；PowerShell 是等价备用方式。
  5. 安装器在复制应用和创建桌面快捷方式成功后，使用部署目录内的 `vc_redist.x64.exe /install /quiet /norestart` 自动安装 VC x64 运行库；退出码 `0`、`3010` 为成功，其他退出码必须失败并提示手动执行路径。
  6. 便携 ZIP 的 README 明确 Qt 运行时已随包提供，且可手动执行包内 `vc_redist.x64.exe`。
  7. 验证脚本解析、交付物运行时文件、VC 安装成功/需重启/失败分支、安装复制/快捷方式/启动回归及 ZIP 无开发机绝对路径。
- Risk level and approval-needed actions: 低风险本地交付变更；不得推送、部署、合并 `main`、切换/创建分支或新增依赖。此目标替代“仅生成外部 Installer ZIP”的使用方式。VC 运行库安装失败会阻止安装成功，用户可按错误信息手动执行部署目录内的安装程序。
- Open question: 无。终端用户无 Qt/MSVC 开发环境不是本次发布验收前置条件；独立测试应验证运行时文件与安装器分支行为。
